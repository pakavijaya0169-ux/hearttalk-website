# HeartTalk phone OTP: recommended production architecture

## Use Supabase Auth as the OTP authority
Keep the existing browser calls:
- `supabaseClient.auth.signInWithOtp({ phone, options: { channel: "sms" } })`
- `supabaseClient.auth.verifyOtp({ phone, token, type: "sms" })`

Supabase Auth generates, stores, expires, rate-limits, verifies the OTP, and issues the real authenticated session. Do not replace this with a custom OTP table or mint JWTs in browser code.

## Custom SMS delivery hook
Deploy `supabase/functions/hearttalk-send-sms/index.ts` as an Edge Function with JWT verification disabled because Supabase Auth calls it before a user session exists. The hook verifies Supabase's Standard Webhooks signature before reading the OTP.

Required Edge Function secrets:
- `SEND_SMS_HOOK_SECRETS`: exact signing secret generated by Supabase Auth Hooks (format begins `v1,whsec_`). Never commit it.
- `SMS_GATEWAY_URL`: HTTPS API endpoint of the chosen SMS gateway.
- `SMS_GATEWAY_API_KEY`: API key for that gateway.

The generic adapter expects a Bearer-authenticated HTTPS POST with JSON `{ "to": "+91...", "message": "..." }`, and a 2xx response means accepted. This is only an adapter contract, not a configured provider. Match the adapter to the selected provider's actual API before enabling it.

In Supabase Dashboard:
1. Authentication -> Hooks -> Send SMS.
2. Select HTTP hook and choose the deployed `hearttalk-send-sms` function URL.
3. Add the signing secret generated for this hook.
4. Save and test with a real phone number only after an SMS provider is configured.

## Why this architecture
Supabase's Send SMS Auth Hook lets a custom SMS provider deliver Supabase-generated OTPs while preserving Supabase Auth's verification and session flow. The hook receives `user.phone` and `sms.otp`; it returns HTTP 200 after the provider accepts the message. The existing `verifyOtp` call then verifies the code and creates the normal Auth session.

## Isolated prototype files
The separate `hearttalk_phone_otps` table and `request-phone-otp` / `verify-phone-otp` functions are an isolated prototype. Do NOT deploy or wire them into production login: they do not issue a Supabase Auth session and are not required when using the Auth Send SMS Hook.
